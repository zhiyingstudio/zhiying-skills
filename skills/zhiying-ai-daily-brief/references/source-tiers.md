# 信息源分级与可信度判断

判断一条 AI 信息是否可信，先看来源，再看内容。**同一件事，来源不同，可信度差三个数量级。**

---

## 一、可信度五级

| 级别 | 来源类型 | 采信方式 |
|---|---|---|
| **A 级** | 官方一手：公司官方博客/新闻稿、SEC/工商登记文件、政府公告、开源仓库 commit、论文原文 | 可直接引用，作为事实 |
| **B 级** | 权威二手：主流科技媒体（有署名记者、有信源核实流程）、行业数据库 | 可引用，标注二手来源 |
| **C 级** | 一般二手：内容站、聚合号、翻译搬运 | 需交叉验证，不单独作为依据 |
| **D 级** | 匿名信源：知情人士、内部员工爆料 | 标注「未经证实」，不给结论 |
| **E 级** | 自媒体、营销号、AI 生成的伪新闻 | 不采用 |

## 二、各类信息的可靠来源

### 2.1 模型与能力

| 信息 | 首选来源 |
|---|---|
| 模型发布 | 官方博客、官方 X/微博账号、HuggingFace 模型卡 |
| 能力评测 | 官方技术报告、独立评测榜（注意榜单是否有商业合作） |
| 开源发布 | GitHub 仓库、模型权重页、许可证文件 |

**警惕**：「某评测显示超越 GPT」——先查该评测榜是否由发布方赞助。

### 2.2 产品与商业

| 信息 | 首选来源 |
|---|---|
| 产品上线 | 官方更新日志（changelog）、应用商店版本记录 |
| 定价变化 | 官方定价页（截图存证，价格常改） |
| 用户数据 | 官方披露 > 第三方统计（SimilarWeb 等仅作趋势参考） |

### 2.3 资本与并购

| 信息 | 首选来源 |
|---|---|
| 融资 | 公司官方公告、投资方公告、SEC Form D |
| 收购 | 双方公告、监管审批文件 |
| 估值 | 融资公告中的口径（区分投前/投后） |

**警惕**：媒体爆料的"正在洽谈"多为早期信息，常无下文。标注「洽谈中」，不写成「已收购」。

### 2.4 政策与监管

| 信息 | 首选来源 |
|---|---|
| 国内政策 | 政府官网原文（国务院、工信部、网信办等） |
| 国际政策 | 官方法规原文、官方新闻稿 |
| 标准规范 | 标准委、行业协会正式发布稿 |

**铁律**：政策类信息必须引用**原文表述**，不得转述、不得概括成"更宽松/更严格"。

### 2.5 开源与工具

| 信息 | 首选来源 |
|---|---|
| 项目发布 | GitHub Releases、commit 记录 |
| 活跃度 | star 增速、fork 数、最近提交时间（三者合看，单看 star 会误判） |
| 许可证 | LICENSE 文件原文（MIT/Apache/AGPL 差别巨大） |

## 三、交叉验证规则

单一来源不足以支撑"重点"判定时，用以下方法：

1. **时间线对齐**：多个来源的发布时间是否一致？时间差过大说明有环节在搬运。
2. **数字比对**：不同来源报的金额、参数量是否一致？不一致时取官方口径并标注分歧。
3. **利益相关排查**：该来源是否与被报道对象有商业关系？
4. **反向检索**：有没有辟谣信息？搜「事件名 + 辟谣 / 否认 / 澄清」。

## 四、危险信号清单

出现以下任一，降级处理或剔除：

- [ ] 标题含「震惊」「重磅」「炸裂」「颠覆」
- [ ] 全文没有一处可点击的原始来源
- [ ] 通篇「据悉」「业内人士称」而无具体人物
- [ ] 数字异常整齐（如"提升300%"无基线说明）
- [ ] 配图为明显 AI 生成且与内容无关
- [ ] 发布账号无历史记录或历史内容全是搬运
- [ ] 正文含营销导流链接
- [ ] 与已知事实冲突（如称某闭源模型开源）

---

## 五、来源标注格式

正文中统一使用：

```
来源：官方博客（2026-03-05）
来源：路透社（2026-03-05，二手）
来源：知情人士爆料（未经证实）
```

**关键**：日期必须写，便于读者判断时效。二手来源必须标「二手」。未证实的必须标「未经证实」。
