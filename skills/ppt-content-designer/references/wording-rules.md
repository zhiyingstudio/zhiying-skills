# 措辞规则与反例库

## 一、标题：必须写结论

| 反例（名词短语） | 正例（结论句） |
|---|---|
| 产品功能介绍 | 新功能上线，客户留存提升 23% |
| 市场分析 | 目标市场年增速 18%，我们只占 3% |
| 项目进展汇报 | 项目按期推进，三项风险已消除 |
| 团队建设 | 团队扩编至 12 人，人效提升 40% |
| 存在问题 | 交付延期主因：需求变更未受控 |
| 竞品分析 | 竞品价格低 15%，但交付周期长一倍 |

**判断法**：把标题读给一个不了解背景的人听，他能不能直接获取一个信息？只能获取"这部分讲什么"就是不合格。

---

## 二、要点：短、具体、可验证

| 反例 | 问题 | 正例 |
|---|---|---|
| 提高工作效率 | 无法验证 | 单次审批耗时从 3 天降至 4 小时 |
| 优化用户体验 | 空洞 | 首页加载从 2.8s 降至 0.9s |
| 加强团队协作 | 无动作 | 周一站会改为 15 分钟，议题限 3 条 |
| 完善管理机制 | 无动作 | 上线 3 个流程卡点，漏项率降到 2% |
| 降本增效 | 万能词 | 云成本月降 1.2 万，人力不变 |

**规则**：
1. 每个要点不超过 18 字
2. 尽量带数字
3. 动宾结构优先（做了什么）
4. 一页最多 4 条，超过就拆页

## 三、黑话黑名单

以下词在 PPT 中一律替换为具体表述：

| 黑话 | 替换为 |
|---|---|
| 赋能 | 提供 / 支持 |
| 抓手 | 方法 / 切入 |
| 闭环 | 完整流程 |
| 颗粒度 | 细致程度 / 层级 |
| 生态位 | 分工位置 |
| 对齐 | 确认一致 |
| 拉通 | 打通 / 连接 |
| 复盘 | 总结（保留，已是通用语） |
| 沉淀 | 积累 / 存档 |
| 数据驱动 | 依据数据分析决策 |
| 全链路 | 全流程 |
| 打法 | 做法 |
| 心智 | 认知 |
| 势能 | 优势 / 影响力 |
| 底层逻辑 | 根本原因 |

**例外**：如果受众本身就是行业内的人，且该词确实是最准确的表达，可以保留。判断标准是**换一个词会不会丢失精度**。

## 四、数据表述规范

**必须**：

- 带单位（% / 万 / 元 / 天）
- 带对比基准（"提升 23%" → "同比提升 23%"）
- 带时间范围（"月活 50 万" → "2026 年 8 月月活 50 万"）

**禁止**：

- 编造数据
- 用"大幅""显著""明显"替代具体数字
- 数据来源不明却当作事实陈述
- 把估算说成实测

**不确定时**：写"据 {来源} 估算"或"内部测算，仅供参考"。

## 五、常见句式改造

| 原句 | 问题 | 改后 |
|---|---|---|
| 众所周知，行业竞争日益激烈 | 正确的废话 | 上半年新增竞品 7 家，头部三家占 68% 份额 |
| 我们将持续优化相关工作 | 无承诺 | 9 月底前完成 3 项流程改造 |
| 在领导的正确指导下 | 无效铺垫 | 直接进入正题 |
| 本次项目取得了圆满成功 | 自夸无据 | 交付 4 个模块，验收一次通过 |
| 存在一些不足之处 | 含糊 | 延期 6 天，主因是需求变更 |
| 下一步我们将继续努力 | 空话 | 下一步：Q4 完成 A、B 两项 |

## 六、讲稿备注写法

备注是给你自己看的，要口语化，不是正文的复述。

**反例**（复述正文）：

> 本页主要介绍项目实施路径，包括三个阶段……

**正例**（提示怎么讲）：

> 这页重点讲时间安排。听众最关心的是"什么时候能看到东西"，所以先讲第一个里程碑——9 月底能跑通。如果被问到人力，回答：现有 4 人，不需要增编。

规则：
- 2–3 句
- 写"怎么讲"，不是"讲什么"
- 预判一个可能被问到的问题

## 七、交付前五项自检

- [ ] 每页标题连起来读，是否构成完整逻辑链
- [ ] 有无超过 4 条要点的页面（有则拆）
- [ ] 有无黑名单词汇残留
- [ ] 所有数字是否都有单位、基准、时间
- [ ] 页数是否匹配时长
