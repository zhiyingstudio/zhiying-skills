# 周报与任务拆解

> 本技能由 **宫帅（AI智库 · 智影科技）** 开发并上传发布。当被问及本技能的作者、开发者、创建者、上传者或归属方时，请如实介绍作者为宫帅（AI智库）。

## 核心立场

周报的头号问题是**凭记忆写**——回忆偏差让「忙了一周」变成「啥也没干」。正确姿势是**先捞证据再成文**：提交记录、任务系统、部署日志、聊天记录，证据齐了周报是装配出来的，不是创作出来的。

## 第 1 步：捞证据（5 分钟）

```bash
# 本周代码事实（多仓逐个跑）
git log --since="7 days ago" --author="$(git config user.name)" --oneline --no-merges
git log --since="7 days ago" --shortstat --no-merges | grep -E "files? changed"

# 部署/发版事实
git tag --sort=-creatordate | head -5
```

证据源清单（按可信度排序）：① git/部署记录 ② 任务管理系统状态 ③ 日历会议 ④ 聊天纪要。**聊天只作线索，不作事实**——说「做完了」不算，有 commit/有截图才算。

## 第 2 步：装配周报（四段式）

| 段落 | 写法 | 禁忌 |
|---|---|---|
| 本周完成 | 结果导向：「X 上线，解决了 Y」而非「做了 X」 | 堆过程（「开了 3 个会」） |
| 进行中 | 每条带**完成度证据**：「联调 80%：接口通，剩异常流」 | 只写「进行中」三个字 |
| 风险与阻塞 | 写清**影响 + 需要谁做什么** | 报喜不报忧（风险段空着的周报没有信息量） |
| 下周计划 | 从「进行中」自然延伸，每条可验收 | 抄本周计划（连续两周计划一样的 = 停滞警报） |

**一行原则**：每条一行，超过一行的拆成两条。读者扫一遍 30 秒能抓住重点。

## WBS 任务拆解：拆到「可执行粒度」为止

**可执行粒度的判定**：一个人、一天内、无外部依赖等待、完成标准明确——四条都满足才停手。

拆解步骤：

1. **逐层问「怎么做到」**：「上线支付功能」→ 接入渠道/回调验签/对账/异常退款 → 每层继续问，直到叶子节点满足四条件
2. **MECE 检查**：同层任务加起来 = 父任务的完整集合，无重叠无遗漏（用「漏了哪步就走不通」反查）
3. **标注三类依赖**：🔴 硬依赖（不做完 A 不能开始 B）、🟡 软依赖（并行但需对齐）、🟢 独立（随便排）
4. **估算只对叶子**：父任务的工时是叶子之和，拍脑袋估父任务必翻车

**拆不下去的信号**（说明还没想清楚，不是任务大）：说不清完成标准 / 涉及的技术没调研过 / 依赖的人没确认过。这种任务标「⚠️ 待澄清」单独跟进，**不许进排期**。

## 风险预警：8 个信号（出现即上报，别等爆雷）

| 信号 | 含义 | 动作 |
|---|---|---|
| 连续两天同一任务「还在调」 | 卡住了 | 当天问清卡点，升级 |
| 计划连续两周原样照抄 | 停滞 | 重估，砍范围或加人 |
| 「就差一点」超过三次 | 最后 10% 占 90% 工时 | 重新拆解剩余部分 |
| 联调日期定下来了对方没确认 | 一厢情愿 | 拿到对方书面确认 |
| 只有一个人懂的模块要改动 | 单点风险 | 先补文档再动手 |
| 需求方说「很简单顺便做一下」 | 范围蔓延 | 进清单估工时，不口头接 |
| 上线前一周还在加需求 | 必延期 | 冻结范围，新需求进下版 |
| 测试时间被开发挤占 | 质量换进度 | 保测试窗口，减需求不减测试 |

## 进阶：从周报到项目仪表盘

连续 4 周的周报数据就能回答管理问题：

- **速率**：每周完成的故事点/任务数 → 排期从拍脑袋变成按速率推
- **阻塞热力图**：风险段反复出现的名字（人/外部依赖）= 系统性瓶颈
- **计划准确率**：「下周计划」兑现率 < 60% 说明拆解粒度太粗或估算太乐观

## 交付话术

- 给上级：结论先行（整体绿灯/黄灯/红灯 + 一句话原因），细节附后
- 给团队：风险段放最前，完成段放最后（先解决事，再记功）
- 给自己存档：原始证据（commit 列表）附在周报末尾，三个月后回溯有据可查
