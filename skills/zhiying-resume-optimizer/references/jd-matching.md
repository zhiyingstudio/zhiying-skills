# 岗位匹配分析与关键词策略

## 一、JD 解析四步

拿到招聘要求后，提取四类信息：

### 1. 硬性门槛（必须满足，否则大概率被系统筛掉）

- 学历、专业
- 工作年限
- 必备证书 / 资质
- 必备技能（如"熟悉 Python"）

**处理**：不满足的硬性门槛，简历会被 ATS 直接过滤。若确实不满足，建议用户评估是否值得投递。

### 2. 高频关键词（用于埋词）

统计 JD 中重复出现的名词：

- 工具类：Excel、SQL、Figma、Axure
- 方法论：用户研究、A/B 测试、敏捷开发、OKR
- 领域术语：私域运营、供应链、风控
- 软技能：跨部门协作、项目管理

**处理**：在简历中自然植入，尽量让关键词出现在**前 1/3 版面**。

### 3. 隐含需求（读潜台词）

| JD 表述 | 通常意味着 |
|---|---|
| 抗压能力强 | 工作强度大、可能有加班 |
| 有创业精神 | 岗位边界模糊、可能需要身兼多职 |
| 快速响应业务需求 | 需求变动频繁 |
| 结果导向 | 看产出不看工时 |
| 有较强的自驱力 | 管理较松、需要自己找活 |
| 熟悉各种办公软件 | 可能涉及大量基础事务性工作 |

**处理**：这些点不必写进简历，但可以作为面试准备的提示告知用户。

### 4. 岗位层级判断

- **执行层**：强调具体技能与产出效率
- **骨干层**：强调独立负责模块、解决复杂问题
- **管理层**：强调带团队、跨部门协调、业务结果

**写错层级是常见错误**：应聘执行岗大谈战略，应聘管理岗只讲自己写代码。

## 二、匹配度诊断表

输出格式：

```markdown
| JD 要求 | 你的对应经历 | 匹配度 | 建议 |
|---|---|---|---|
| 3 年以上 B 端经验 | 5 年，2 个 0-1 产品 | 强 | 前置到个人总结 |
| 数据分析能力 | 未体现 | 弱 | 补充：用数据驱动过的决策 |
| 团队管理 | 带过 3 人小组 | 中 | 明确写出管理人数 |
```

匹配度分级：

- **强**：有直接对应的经历 + 有数据支撑
- **中**：有相关经历但不够直接，或缺乏数据
- **弱**：JD 要求但简历未体现

**处理原则**：

1. 强匹配 → 前置、加粗、突出
2. 中匹配 → 补充细节，挖出可量化部分
3. 弱匹配 → 优先挖真实经历；实在没有，用**相邻能力**佐证（如要"数据分析"没有，但有"通过用户反馈迭代产品"，可体现数据敏感度）
4. **绝不虚构**

## 三、关键词埋词策略

### 自然植入的三个位置

1. **个人总结**：一句话里塞进 2–3 个核心关键词
2. **工作经历要点**：动作描述中带出工具与方法
3. **技能栏**：明确列出

### 同义词覆盖

JD 用的词优先，同时补充同义表达：

| JD 用词 | 简历可写 |
|---|---|
| 用户研究 | 用户研究（用户访谈 / 问卷 / 可用性测试） |
| 数据分析 | 数据分析（SQL / Excel / BI 工具） |
| 项目管理 | 项目管理（需求拆解 / 排期 / 风险管理） |

### 红线

**绝对不要**：

- 白字、隐藏文字、极小字号埋词（ATS 可识别，直接淘汰）
- 无意义重复堆砌同一关键词
- 写不具备的技能（面试必翻车）

## 四、不同求职场景的调整

### 校招

- 重点：教育背景、实习、项目、竞赛
- 篇幅：1 页
- 关键词：突出可塑性与学习能力，但要有事实支撑

### 社招跳槽

- 重点：工作成果、项目经验
- 篇幅：2 页（10 年内）
- 关键词：突出独立负责能力与业务结果
- **注意**：近期经历优先，早期经历可压缩

### 转行

- 重点：**可迁移能力**（transferable skills）
- 写法：把过往经历往目标岗位的语言体系上翻译
- 补充：自学/培训/副业/志愿工作中与目标岗位相关的部分
- 示例：教师转产品运营 → 强调"需求洞察、内容设计、效果评估"的能力

### 管理岗

- 重点：团队规模、业务体量、跨部门协作
- 关键词：带团队人数、负责的营收/成本规模、组织建设

## 五、常见拒绝原因自查

投递后无回音，按以下顺序自查：

1. **硬性门槛不符**（学历/年限/证书）→ ATS 直接过滤，无法挽救
2. **关键词命中率低** → 按 JD 重新埋词
3. **无量化结果** → 全是职责描述，看不出能力水平
4. **层级错位** → 应聘执行岗写战略，或反之
5. **页数过长** → HR 没耐心看完
6. **格式混乱** → 表格排版错乱、字体不统一、有错别字

前两项属于可修复问题，建议优先处理。
