# 经历改写公式与动词库

## 一、核心公式

```
动作动词 + 具体对象 + 方法/工具 + 量化结果
```

## 二、四类量化引导

| 类型 | 引导问法 | 示例 |
|---|---|---|
| 规模 | 管多少人 / 多少钱 / 多少量 / 多少并发？ | 维护 3 万用户的数据平台 |
| 效率 | 比以前快多少 / 省多少人力？ | 报表产出从 2 天缩至 2 小时 |
| 增长 | 带来了什么业务变化？ | 转化率从 2.1% 提到 3.4% |
| 质量 | 错误率 / 返工率 / 客诉降了吗？ | 客诉量下降 40% |

无法量化时用**难度与稀缺性**替代：如"主导公司首个跨境结算模块的技术选型"。

## 三、动词库（按场景）

### 管理类

主导、统筹、牵头、组建、优化、推动、协同、拆解、复盘、赋能团队

### 业务增长类

从 0 到 1 搭建、增长、拉升、转化、拓展、盘活、提效、降本

### 技术类

设计、实现、重构、优化、迁移、集成、封装、排查、定位、治理

### 数据类

建模、清洗、分析、挖掘、监控、量化、搭建指标体系、设计埋点

### 沟通协调类

对接、协调、说服、推动落地、跨部门协作、需求梳理

### 避免使用的弱动词

负责（无结果）、参与（无贡献）、协助（无独立价值）、了解（太虚）、跟进（太虚）

**改法**：把弱动词替换成具体动作 + 结果。

| 弱表达 | 强化方向 |
|---|---|
| 负责 XX 工作 | 改为：独立完成 XX，结果为 XX |
| 参与 XX 项目 | 改为：承担 XX 模块，贡献是 XX |
| 协助 XX | 改为：主导 XX 环节，或干脆删除 |

## 四、改写对照表（高频场景）

| 原句 | 改写 |
|---|---|
| 负责公司新媒体运营 | 独立运营 3 个平台账号，6 个月内粉丝从 0 增至 12 万，单条最高阅读 87 万 |
| 参与了系统开发 | 承担订单模块开发，重构查询逻辑使接口响应从 1.2s 降至 180ms |
| 协助完成市场调研 | 主导 200 份用户问卷设计与分析，输出的定价建议被采纳落地 |
| 提升了团队效率 | 引入自动化脚本处理日报，团队每周节省 6 人时 |
| 处理客户投诉 | 建立分级响应机制，投诉平均处理时长从 48h 降至 6h |
| 管理仓库 | 重构库位分区与出入库流程，盘点差异率从 3.2% 降至 0.4% |
| 做过培训 | 设计并主讲新人入职培训，覆盖 120 人次，考核通过率 94% |
| 写了很多文档 | 建立 API 文档规范，覆盖 80+ 接口，新同事上手周期缩短一半 |
| 运营公众号 | 负责选题与撰稿，半年产出 96 篇，平均打开率 8.7%（行业均值 3.1%） |
| 各种日常行政工作 | 删除——无信息量条目只会稀释简历 |

## 五、项目经历写法（技术岗）

```
项目名称 | 时间 | 角色

项目背景：一句话说明要解决什么问题（含规模量级）
我的职责：具体负责哪部分
技术方案：用了什么技术、为什么这么选
技术难点：遇到了什么，怎么解决的
项目成果：上线效果、数据表现、获得什么认可
```

**要点**：难点那一段最有价值——面试官会顺着问，写你有把握答的。

## 六、应届生简历特殊规则

**没有工作经验时，用这四类经历填充**：

| 类型 | 怎么写 |
|---|---|
| 实习 | 按正式工作标准写，有数据就用数据 |
| 项目/课程设计 | 写清你个人负责的部分，不要只写小组做了什么 |
| 竞赛 | 名次 + 规模 + 你解决的问题 |
| 校园经历 | 组织活动的规模、你的角色、可量化的结果 |

**禁止**：把小组作业写成个人成就、把听课经历写成项目经验。

## 七、自检清单

- [ ] 每条经历是否包含结果（数字或难度）
- [ ] 是否出现"负责/参与/协助"开头且无结果的条目
- [ ] "精通/熟练/熟悉/了解"是否与实际能力匹配（宁可降一档）
- [ ] 是否有形容词堆砌（积极主动、认真负责、吃苦耐劳）
- [ ] 是否按目标岗位调整过关键词
- [ ] 页数：应届 1 页 / 10 年内 2 页
- [ ] 无编造数据、无虚构经历
- [ ] 联系方式正确、无错别字
